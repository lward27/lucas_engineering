# ASTRA: Evaluation completion receipts

Source base: `eb13ae51a147969cc8d6ca826d2580f069dfc493`. The earlier source-a2 PHarness diagnostic retained its native result but lost the final Pod/image/exit observation before Kubernetes expiry. Later source38 diagnostics required repeated ad hoc observation code to close that gap. This change extends the existing `lucas-ops evaluation watch` rather than introducing another runner or workflow controller.

The watcher retains native terminal API evidence unchanged and waits for the named Job and owned Pods to terminate within its existing observation deadline. It verifies the native evaluation label, namespace, Job UID and Pod owner references; a recreated or unrelated object cannot replace an earlier observation. Its separate execution receipt contains configured/actual image identities and bounded state/exit fields. It excludes environment variables, arguments, annotations, free-text termination messages and logs.

A missing Job/Pod or unavailable read is an explicit gap. A timeout preserves the pending observation and remote operation. Neither causes redispatch, cancellation, retry-budget expansion or an invented verdict. Saved terminal receipts remain immutable and readable after cleanup, with a retained-evidence marker. `captured` means observed termination data, not successful model work or qualified delivery.
